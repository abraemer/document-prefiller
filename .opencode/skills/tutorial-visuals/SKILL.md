# Regenerate tutorial examples and visuals

## Purpose

Drive the real Electron app with Playwright, capture screenshots, generate the example `.docx` templates, and assemble the demo GIF. The workflow rewrites the committed assets under `docs/tutorial/` so PR diffs show exactly what changed.

## Prerequisites

Every command block starts with the Node pre‑amble required by the repo:

```bash
source ~/.nvm/nvm.sh && nvm use 24 --silent && sleep 1
```

* `ffmpeg` must be on `PATH` for GIF assembly. If it is missing the script still produces PNGs and fails loudly on the GIF step.
* On Linux a graphical session is needed – `DISPLAY` or `WAYLAND_DISPLAY` must be set.
* Run from the repository root.

## Usage

```bash
pnpm generate:visuals          # alias for the full capture workflow
node .opencode/skills/tutorial-visuals/scripts/capture-visuals.mjs [--keep] [--skip-gif]
```

To regenerate only the template `.docx` files:

```bash
node .opencode/skills/tutorial-visuals/scripts/generate-templates.mjs [--out <dir>]
```

* `--keep` preserves temporary directories for debugging.
* `--skip-gif` runs the PNG capture path while skipping the GIF step when `ffmpeg` is unavailable.

## What a run produces and what is tracked

* `docs/tutorial/templates/*.docx` – byte‑reproducible example templates.
* `docs/tutorial/outputs/*.docx` – filled documents generated by the app.
* `docs/tutorial/assets/0N-*.png` – step screenshots taken during the run.
* `docs/tutorial/assets/demo.gif` – the animated demo shown in the README.

All of these files are committed, so reviewers can see visual updates directly in the PR diff. Temporary directories (`/tmp/...`) are cleaned automatically unless `--keep` is passed.

## Gotchas

* pnpm commands must be prefixed with `--config.verify-deps-before-run=false` while the lockfile entries are fresh (younger than one day).
* Never commit `.replacement-values.json`; the capture script always writes it into a temporary copy of the templates.
* After UI changes re‑run the skill to refresh the screenshots.
* The generation script forces fixed timestamps inside the ZIP files, guaranteeing byte‑identical output across runs.
* The run asserts dialog‑mock call counts, PNG‑vs‑window bounds, and output content. Do not relax these assertions – they protect the regression test suite.
* The generated PNG and GIF files are part of the repo; they are not rebuilt by CI.

## Related

The unit test `tests/unit/tutorial-templates.test.ts` locks the committed templates and outputs. Running the skill updates those artifacts, and the test suite verifies them during `pnpm test:run`.
